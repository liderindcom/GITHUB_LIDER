Acesso controlado
Onboarding de usuários
Gere localmente a chave e o passaporte de entrada para um novo operador do MAOADC Coliseum.
provisionamento administrativo

          
4binários disponíveis
localgeração de chaves
SSHcanal de conexão
manualaprovação final

          
Fluxo
Cadastrar novo usuário
  1. Envie o instalador correspondente ao computador do novo usuário.
  2. O usuário executa o instalador, cria o PIN/senha e gera o passaporte.
  3. O usuário envia a chave pública para o administrador por canal seguro.
  4. O administrador salva a chave pública no cadastro autorizado do servidor.
Regra de segurança
O usuário nunca envia PIN, senha ou chave privada. O servidor salva somente a chave pública. O Painel Líder orienta o fluxo; a gravação definitiva depende do backend de autorização.

Provisionamento do servidor
Criar usuário Linux e ativar Herdr
root-only
Depois de receber somente a chave pública, execute o assistente no servidor:
sudo bash /home/administrador/maoadc-arena/deployment/access-bootstrap/provision-onboard-user-interactive.sh
Modo direto/home/administrador/maoadc-arena/deployment/access-bootstrap/provision-onboard-user.sh --user <login_individual> --full-name "Nome Completo" --project lider_site --public-key-file /caminho/chave.pub --scope "Escopo autorizado"
O que o provisionador faz
Cria uma conta Linux sem sudo/docker, instala o binário Herdr se necessário, cria ~/.config/herdr, instala somente a chave pública, registra o mandato e configura o auto-start individual do Herdr. O navegador nunca cria usuários nem recebe a chave privada.

          
Passo final: depois de receber a chave pública, o administrador deve executar o provisionador root-only. Não usar o `data.js` nem o navegador para guardar chaves.

Como interpretar

                
Hierarquia dos protocolos

              

            

            

              

                
1. Protocolo normativo

                
Define princípios, tiers, limites, segurança e comportamento dos agentes. A fonte canônica vigente tem autoridade normativa.

              

              

                
2. Harness e gates

                
Transformam a norma em projeto, fase, papel, bloqueio, teste, auditoria e transição verificável.

              

              

                
3. BICO e execução

                
Distribuem tarefas assíncronas entre agentes. Um BICO executa uma frente; não cria autorização sozinho.

              

              

                
4. CODE e release

                
Registram arquivos, decisão, testes, auditor, commit, risco e estado da entrega para continuidade e auditoria.

              

              

                
5. RAG e conhecimento

                
Recuperam contexto de fontes com proveniência. Texto recuperado é contexto não confiável, nunca uma ordem.

              

              

                
6. Mapas e snapshots

                
Constelações, bootstrap e relatórios ajudam a localizar relações e evidências, mas não autorizam produção.

              

            

            
Regra de autoridade: fonte canônica e gates governam; decisões explicam; BICOs executam; CODE prova; snapshots informam. Se o status for pilot, parcial, local ou documentado, não trate como homologação de produção.
